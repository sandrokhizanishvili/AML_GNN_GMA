# AML_GNN_GMA

Anti-Money Laundering (AML) detection using Graph Neural Networks, based on the paper **"Realistic Synthetic Financial Transactions for Anti-Money Laundering Models"** by Altman et al. (2023).

The project treats financial transactions as a directed graph (accounts are nodes, transactions are edges) and trains GNN models to classify each transaction as legitimate or part of a laundering scheme. The central research question is whether **manual feature engineering** — specifically Graph Feature Preprocessor (GFP) structural features and Random Walk Positional Encoding (RWPE) — can compensate for the expressiveness ceiling imposed by the 1-Weisfeiler-Leman test on standard message-passing GNNs.

Three architectures (GINe, GATv2, PNA) are each evaluated in five configurations (Baseline, GFP, RWPE, GFP+RWPE, GFP with Split Projection), plus XGBoost as a non-graph baseline.

## Setup

The `Data/` folder is not included in this repository. Before running any notebook, create it and populate it:

1. Create a `Data/` folder in the project root.
2. Download the **LI-Small** files from Kaggle:
   [https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml)
3. Place these three files in `Data/`:
   - `Data/LI-Small_Trans.csv`
   - `Data/LI-Small_accounts.csv`
   - `Data/LI-Small_Patterns.txt`

All remaining files in `Data/` are generated automatically by the data preparation notebooks.

## Notebooks

### Step 1 — Exploratory Data Analysis

#### `EDA.ipynb`
Thorough analysis of the raw LI-Small dataset before any modelling. Covers:
- Class imbalance (0.0515% laundering rate, 1,941:1 ratio)
- Transaction amount distributions (log-normal, heavy-tailed) and laundering vs. legitimate comparison
- Temporal patterns: daily volume, hourly and day-of-week laundering rates (weekends show ~2× average rate)
- Payment format analysis: ACH carries ~6× the average laundering rate
- Currency analysis: mismatch rate (1.43%) carries zero laundering signal in this dataset
- Network topology: degree distributions (power-law, scale-free), self-loop analysis, hub account behaviour
- Account entity type analysis: Individual accounts have ~2× average laundering rate
- Laundering typology distribution: 117 attempts across 8 pattern types (Stack and Bipartite most common)
- Outputs feature engineering decisions that feed directly into the data preparation notebooks

---

### Step 2 — Data Preparation

#### `Data_prepration.ipynb` — Baseline Pipeline
Builds the baseline graph dataset used by all Baseline and RWPE model notebooks. Steps:
1. Loads `LI-Small_Trans.csv` and `LI-Small_accounts.csv`
2. Engineers **16 edge features**: log-amount, currency mismatch flag, cyclic hour/day-of-week encodings, is-weekend, is-ACH, is-self-loop, payment format one-hot (7 categories)
3. Engineers **5 node features**: normalised bank ID, entity type one-hot (Corporation, Individual, Partnership, Sole)
4. Builds a contiguous account-to-integer index map (`account_to_idx.pkl`)
5. Applies a 60/20/20 **temporal split** (no leakage): train cut at Sep 6, val cut at Sep 8
6. Constructs three **cumulative PyG graph snapshots** using the paper's protocol: `train_graph.pt` (train edges only), `val_graph.pt` (train+val edges, eval mask on val only), `test_graph.pt` (all edges, eval mask on test only)

Saves: `edge_features.csv`, `node_features.csv`, `account_to_idx.pkl`, `train_graph.pt`, `val_graph.pt`, `test_graph.pt`

#### `Data_preparation_gfp.ipynb` — GFP Pipeline
Extends the baseline pipeline by computing **IBM SnapML Graph Feature Preprocessor (GFP)** structural edge features and appending them to the baseline features. Steps:
1. Repeats baseline feature engineering to produce the 16-dim baseline edge vector
2. Runs IBM SnapML's `GraphFeaturePreprocessor` on the transaction graph, which computes 61 AML-specific structural features per edge: cycle membership, fan-in/fan-out counts, scatter-gather and gather-scatter pattern statistics, vertex degree statistics, and temporal flow features
3. Concatenates baseline (16-dim) + GFP (61-dim) = **77-dim edge feature vector**
4. Fits and saves a `RobustScaler` and `StandardScaler` for reproducible inference
5. Saves feature column metadata to `feature_meta_gfp.json`
6. Constructs the same three cumulative graph snapshots with the augmented features

Saves: `edge_features_gfp.csv`, `node_features_gfp.csv`, `account_to_idx_gfp.pkl`, `feature_meta_gfp.json`, `robust_scaler_gfp.pkl`, `standard_scaler_gfp.pkl`, `train_graph_gfp.pt`, `val_graph_gfp.pt`, `test_graph_gfp.pt`

---

### Step 3 — Model Training

All model notebooks share the same training protocol:
- **Mini-batch training** via PyG `LinkNeighborLoader` with neighbourhood sampling [100, 100] (matching the paper)
- **Temporal graph snapshots**: cumulative val/test graphs ensure historical context is available during message passing
- **Class imbalance**: handled via `pos_weight` in BCE loss (no oversampling)
- **Optimiser**: Adam with cosine annealing LR schedule
- **Checkpointing**: best validation AUC; threshold optimised on validation set for final test evaluation
- **Output**: model checkpoint (`.pt`) and prediction CSVs for all splits saved to `Models/`

#### Required inputs per notebook group

| Notebook group | Requires |
|---|---|
| Baseline, RWPE | `train_graph.pt`, `val_graph.pt`, `test_graph.pt` (from `Data_prepration.ipynb`) |
| GFP, GFP+RWPE, GFP Enhanced | `train_graph_gfp.pt`, `val_graph_gfp.pt`, `test_graph_gfp.pt` (from `Data_preparation_gfp.ipynb`) |

---

#### GINe (Graph Isomorphism Network with Edge Features)

GINe uses `GINEConv` layers where edge features modulate neighbour messages: `agg = SUM[ReLU(h[u] + e_{uv})]`. The decoder concatenates sender embedding, receiver embedding, and seed edge features for classification: `concat(h[src], h[dst], e_seed) → MLP → logit`.

| Notebook | Config | Node dim | Edge dim | Epochs |
|---|---|---|---|---|
| `baseline_model.ipynb` | Baseline | 5 | 16 | 10 |
| `gine_rwpe.ipynb` | RWPE | 13 (5 + 8 RWPE) | 16 | 20 |
| `gine_gfp.ipynb` | GFP | 5 | 77 | 20 |
| `gine_gfp_rwpe.ipynb` | GFP + RWPE | 13 | 77 | 20 |
| `gine_gfp_enhanced.ipynb` | GFP + Split Projection | 5 | 77 | 20 |

The **Split Projection** variant (`gine_gfp_enhanced.ipynb`) uses a modified decoder that projects the 16 baseline edge features and 61 GFP structural features through separate linear layers before concatenating, preventing the structural features from dominating the transaction-level signal.

---

#### GATv2 (Graph Attention Network v2)

GATv2 uses multi-head attention to compute per-neighbour importance weights during message passing. Edge features (77-dim for GFP variants) are concatenated with source/target node features to compute attention scores, allowing the model to selectively focus on the most informative neighbours.

| Notebook | Config | Node dim | Edge dim | Epochs |
|---|---|---|---|---|
| `gat_baseline.ipynb` | Baseline | 5 | 16 | 20 |
| `gat_rwpe.ipynb` | RWPE | 13 (5 + 8 RWPE) | 16 | 20 |
| `gat-gfp.ipynb` | GFP | 5 | 77 | 20 |
| `gat_gfp_rwpe.ipynb` | GFP + RWPE | 13 | 77 | 20 |
| `gat_gfp_enhanced.ipynb` | GFP + Split Projection | 5 | 77 | 20 |

---

#### PNA (Principal Neighbourhood Aggregation)

PNA applies multiple aggregation functions simultaneously (mean, max, min, std) combined with degree-aware scalers (identity, amplification, attenuation), producing richer node embeddings than single-aggregator GNNs. Degree statistics are pre-computed from the training graph to calibrate the scalers.

|---|---|---|---|---|
| `model_pna.ipynb` | Baseline | 5 | 16 | 20 |
| `pna_baseline_rwpe.ipynb` | RWPE | 13 (5 + 8 RWPE) | 16 | 20 |
| `pna-gfp.ipynb` | GFP | 5 | 77 | 20 |
| `pna_gfp_rwpe.ipynb` | GFP + RWPE | 13 | 77 | 20 |
| `pna-gfp-enhanced.ipynb` | GFP + Split Projection | 5 | 77 | 20 |

---

#### XGBoost (Non-Graph Baseline)

#### `xgboost_gfp_rwpe.ipynb`
Trains an XGBoost classifier on the GFP + RWPE feature set as a non-graph point-of-comparison. Each transaction is represented as a flat feature vector (GFP structural features + RWPE node positional encodings for sender and receiver) with no message passing. Provides an upper-bound estimate of what is achievable from the engineered features alone, without graph structure exploitation. Saves the model in JSON format, feature importance plot, PR curves, and prediction CSVs.

---

### Step 4 — Results Analysis

#### `models_results_analysis.ipynb`
Loads prediction CSVs from all 16 models in `Models/` and produces a comprehensive comparison. Sections:
- **Point estimates**: ROC-AUC, PR-AUC, F1, and MCC for every model × split (train/val/test), evaluated both at threshold=0.5 (paper-comparable) and at threshold optimised on the validation set
- **Bootstrapped confidence intervals**: 100 stratified bootstrap iterations per model on the test set, with 95% CI error bars on PR-AUC, F1, and MCC
- **Top-K analysis**: Precision@K and Recall@K (K = 1%, 5%, 10%, 15%, 20%, 25%) per architecture, measuring operational utility when analysts can review only a fixed fraction of flagged transactions
- **Typology breakdown**: per-laundering-pattern performance (Fan-In, Fan-Out, Gather-Scatter, Scatter-Gather, Cycle, Random, Bipartite, Stack) and integration-stage laundering, using bootstrapped PR-AUC/F1/MCC with a fixed 90/10 legitimate/laundering sampling ratio
- Outputs grouped bar charts comparing all feature configurations across architectures
